## 📌 TL;DR

- **起步卖「软件授权」，不卖「AI 调用」**：用户自备 API Key，厂商不为推理买单 → 收费模型极简（试用 → 买断），先把「能不能收钱」跑通。
- **三档模型**：① 试用（本地限次，免费）→ ② 买断（永久激活，199–399 元）→ ③ 订阅（二期，含内置额度、厂商代付 API，30–80 元/月）。
- **收费闭环**：支付成功 → 后端签发 License（RSA 签名）→ 用户导入 → App **离线验签**激活（契合「本地优先/隐私」卖点）。
- **收款通道分步**：手动发码（0 成本验证）→ 聚合支付自动发码 → 个体户 + 微信/支付宝商户号（正规）。
- **二期才碰「厂商代付」**：需账户体系 + 额度 + LLM 代理，带来 API 成本与数据合规义务，坚决放在验证完付费意愿之后。

## 1. 收费模型设计

### 1.1 为什么起步卖「授权」不卖「调用」
单次分析 API 成本 ≈ 0.02 元、活跃用户月成本 ≤ 2 元（见总体方案数据依据）。若起步就「按次/订阅含 API」，厂商需**先垫付**并承担合规义务，且要建账户/额度/代理系统，复杂度高。而「用户自备 Key」时，推理费是用户自己的，厂商**零边际成本**——此时收费对象纯粹是「软件授权」，模型最简、风险最低、最快见钱。

### 1.2 三档模型定义
| 档位 | 价格建议 | 能力 | 适用阶段 |
|------|---------|------|---------|
| 试用（Trial） | 免费 | 限次完整分析（默认 3 次），不阻塞隐私浏览 | v0.5 起 |
| 买断（Perpetual） | 199–399 元 | 永久激活全部功能，需自备 API Key | v0.5 起（首推） |
| 订阅（Subscription） | 30–80 元/月 | 免 Key（厂商代付额度）+ 全部功能，到期降级试用 | v1.0（二期） |

### 1.3 定价锚点
- 买断 199–399 元：对标 XMind 终身 399、WPS 专业版 <200 元/年，规避「千元情感导师」区与「订阅焦虑」。
- 订阅 30–80 元/月：低客单降低决策门槛，二期用于消除 Key 摩擦、拉升转化。
- 免费试用：降低首单心理门槛，是转化临门一脚。

### 1.4 与 API Key 的关系
- **起步（v0.5）**：所有付费档均「用户自备 Key」，厂商不碰 API。
- **二期（v1.0）**：订阅档改「厂商代付内置额度」，用户彻底免 Key；买断档可保留自备 Key 或加购小额内置额度。

## 2. 支付与收款通道

### 2.1 通道对比
| 通道 | 资质要求 | 自动发码 | 费率/成本 | 合规风险 | 适用阶段 |
|------|---------|---------|-----------|---------|---------|
| 手动转账 + 人工发码 | 无 | 否 | 0 | 低（但规模受限） | MVP-1 验证需求 |
| 聚合支付（码支付/易支付/虎皮椒类） | 免营业执照 | 是（回调） | 较高（约 1–3%+） | 中（需甄别合规主体） | MVP-2 |
| 个体户 + 微信/支付宝商户号 | 营业执照 | 是（回调） | 标准（约 0.6%） | 低（最正规） | MVP-2 后 |
| 内容平台（面包多/爱发电/小报童） | 平台入驻 | 弱 | 平台抽成 | 低 | 辅助/资料包 |

> ⚠️ 微信/支付宝**个人收款码用于经营性收款**违反其服务协议，长期有风控冻结风险，**不建议作为正式收款方式**。

### 2.2 推荐路径
1. **手动发码起步**：用户转账 → 运营用签发脚本生成 License → 发回。0 成本验证「有人愿意付」。
2. **接聚合支付**：拿到成功回调 → 自动签发并下发 License，去人工。
3. **升级个体户 + 商户号**：正规、可开发票、费率低，作为规模化后的底座。

### 2.3 回调与发码流程（自动化）
```
用户支付 → 支付方回调(订单号/金额) → 后端验签回调 →
   调用签发服务(issue_license) → 生成 License 字符串 →
   返回给用户(页面/邮件/短信) → 用户导入 App → 本地验签激活
```
签发服务为后端小程序（FastAPI/云函数即可），**私钥仅存后端**，公钥内嵌 App。

### 2.4 合规
- 正式经营性收款建议注册**个体工商户**（流程快），开通商户号。
- 必备：**隐私政策、用户协议、退款条款**（总体方案 P0-2）；按用户要求开具发票。
- 明示定价与「不承诺包挽回」等边界，与 PUA/情感导师切割。

## 3. 授权激活机制（技术规格）

### 3.1 License 结构
明文 JSON（示例）：
```json
{
  "v": 1,
  "tier": "perpetual",          // trial | perpetual | subscription
  "edition": "pro",
  "issued": 1730000000,         // Unix 秒
  "expires": 0,                 // 0 = 永久；订阅填到期时间戳
  "hwid": "",                   // 可选：为空=不绑机，否则为设备哈希
  "seat": 1,
  "nonce": "随机串"
}
```
**License 字符串** = `base64(json) + "." + base64(rsa_pkcs1_v1_5_sign(sha256(json)))`。

### 3.2 离线验签
App 内置**厂商公钥**（编译期内嵌，轻度混淆）。激活时：拆分 → 用公钥验签 JSON → 校验 `expires` → （若 `hwid` 非空）比对本地 HWID 哈希。全程**不依赖服务器**，契合隐私定位。

### 3.3 三档验证逻辑
- **Trial**：无 License，依赖本地试用计数（见 §4）。
- **Perpetual**：验签通过且 `expires==0` 或未来 → 永久解锁。
- **Subscription**：验签通过且 `expires` 在未来 → 解锁；启动时检查，过期 → 降级 Trial 并提示续费（允许离线宽限期，如 7 天）。

### 3.4 设备绑定（HWID）
- 本地计算稳定哈希：`sha256(磁盘序列号 + 主板序列号 + OS 安装 ID + 固定盐)`，**不采集任何可识别个人的明文**，符合隐私品牌。
- 提供「解绑/换机」入口（买断手动、订阅走账户）避免误绑致失效。
- 若用户反感绑定，`hwid` 留空即不绑机（牺牲一点防共享换体验）。

### 3.5 防滥用边界
桌面 DRM 不可能绝对防破解，接受该现实；真正护城河是**持续更新 + 内置额度服务 + 社区**。验签做"足够提高门槛"即可，不投入重装甲。

### 3.6 与现有 config 体系集成
现有 `app/config.py` 已有 DEFAULTS + 点号读写 + **差分保存 + 版本迁移**（见 README §5.4 E33）。新增键走同一机制，避免"旧值压住默认值"：
- `trial_uses_remaining`（默认 3，可迁移）
- `license`（字符串）、`activated`（bool）、`license_tier`、`license_expires`
用户主动改过的项原样保留，迁移幂等。

## 4. 试用额度机制

- **计数与持久化**：`trial_uses_remaining` 存于 config（差分保存）。每次"完成一次完整分析闭环"递减 1。
- **耗尽后行为**：分析面板显示锁定态 + 「输入激活码」按钮；**不阻塞隐私浏览、不阻塞查看已生成结果**。
- **轻度防篡改**：计数写入受 config 完整性约束；不追求绝对防刷（与 §3.5 同一原则），必要时首启 fingerprint 限制。
- **重置边界**：重装不清零（否则丧失意义）；换机/重置走人工或账户（订阅档）。

## 5. 二期：订阅 + 厂商代付（边界说明，不本期实现）

### 5.1 需要的能力
用户账户体系、余额/额度、一个**服务端 LLM 代理**（厂商持 Key，转发请求并扣额度）。约 8 人日（总体方案 P1-1）。

### 5.2 API 成本兜底
单活跃用户月成本 ≤ 2 元，占合理订阅价 < 5%，毛利可行（数据依据已证）。

### 5.3 数据合规义务
厂商代付意味着聊天上下文经代理 → 须明确告知、加密传输、最小化留存，并评估是否触发 PIPL 申报/数据出境义务（总体方案待确认项②）。

## 6. 落地分阶段

| 阶段 | 交付 | 工作量 | 依赖 |
|------|------|--------|------|
| **MVP-1** | 试用计数 + 激活弹窗 + 本地 RSA 验签 + 手动签发脚本（`scripts/issue_license.py`） | 1–2 人日 | config 迁移体系（已有） |
| **MVP-2** | 聚合支付回调自动发码 + 隐私政策/用户协议 + 首屏显著告知（P0-2）+ 安装器/签名 | 3–5 人日 | MVP-1 验签；总体 P0-3 |
| **MVP-3（二期）** | 订阅档 + 厂商代付代理 + 用户账户 + 额度 | 8 人日 | MVP-2；个体户/商户号 |

## 7. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| License 被破解/共享 | 中 | 接受；靠更新+服务+轻度 HWID；不投重装甲 |
| 支付通道合规（聚合主体/个人码） | 中 | 甄别合规主体；尽快转个体户+商户号 |
| HWID 误绑导致换机失效 | 低–中 | 提供解绑/重置入口；默认可不绑机 |
| 订阅代付 API 成本与数据合规 | 中 | 二期才做；明确告知+加密+最小化留存 |
| 退款纠纷 | 低–中 | 用户协议写清冷静期/首单边界（待确认⑤） |
